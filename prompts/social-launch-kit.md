# Social Launch Prompt Kit

These prompts support grant communication after technical proof exists. They must not invent adoption, performance, funding, partnerships, security, or decentralization claims.

## 1. Social strategy architect

```text
Act as a senior social strategy architect for an open-source Solana developer tool. Analyze the niche, target developers, adjacent tools, proof already collected, and grant goals. Build a 90-day strategy for [platforms] with positioning, voice, three content pillars, growth, engagement, conversion, KPIs, and weekly actions. Label every unverified claim and exclude vanity metrics from success criteria.
```

## 2. Content pillar builder

```text
Develop five content pillars for SolContinuity. For each, provide educational, technical-demonstration, founder-learning, community-question, short-video, carousel, and call-to-action ideas. Every idea must connect to reproducible evidence: tests, traces, public code, failure simulations, or external adopter feedback.
```

## 3. 30-day content calendar

```text
Create a 30-day content calendar with Day, Pillar, Topic, Hook, Format, Proof Artifact, Primary Goal, and CTA. Balance technical education, build logs, failure demonstrations, design decisions, community questions, and grant progress. Never claim production readiness before the proof gate is green.
```

## 4. Scroll-stopping post creator

```text
Write a post about [topic] using one contrarian but accurate hook, concise evidence, one developer takeaway, one limitation, and one CTA. Do not use hype words such as uncensorable, revolutionary, guaranteed, or trustless unless the evidence and architecture justify them.
```

## 5. Short-form technical video

```text
Write a 60-second script in Dialogue and Visuals/B-roll columns. Show a real single-RPC failure, the multi-RPC recovery path, the evidence report, and the remaining limitation. End by inviting developers to reproduce the test.
```

## 6. Community growth system

```text
Design a developer-community system based on issue discussions, reproducible failure cases, office hours, contribution guides, and external-adopter tests. Optimize for durable contributors and verified integrations, not follower count.
```

## 7. Performance analyzer

```text
Analyze post text plus views, comments, shares, saves, click-through, repository visits, installs, issue creation, and external test completions. Explain what drove meaningful developer action and recommend the next evidence-backed experiments.
```
