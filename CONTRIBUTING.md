# Contributing

1. Start from an issue or a precisely stated failure.
2. Make the smallest reversible change that addresses one cause.
3. Preserve unrelated work and never commit secrets.
4. Add the narrowest useful test.
5. Run `npm run verify` before requesting review.
6. Attach evidence for UI or browser-path changes.

Every pull request must state reality, change, proof, residual risk, rollback, and next gate.
