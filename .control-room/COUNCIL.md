# Founder AI Council Contract

Status: active control-room documentation for `jussray/solcontinuity`.

The Council is a multi-model reasoning/review layer. It cannot override current repository/provider/runtime evidence, security boundaries, canonical verification, live-network gates, or founder authority.

## Neutral shared Council invariant

The Council is a neutral shared protocol/ledger connecting four first-class standalone peers: Founder Control Room, Chief AI, Sol, and PromptOS.

- Founder Control Room is standalone founder operating/build intelligence.
- Chief AI is standalone executive synthesis/reasoning intelligence.
- Sol is standalone challenge/evaluation/continuity intelligence.
- PromptOS is standalone prompt/workflow/compiler/routing intelligence.

No core peer owns the shared Council layer. Each repository owns only its project-local Council adapter, evidence bindings, receipts, routing constraints, and authority membrane at `.control-room`. Core operation must survive Council unavailability.

External models such as ChatGPT, Claude, Muse, DeepSeek, Perplexity, Gemini, local models, and future providers are replaceable Council seats, not permanent infrastructure. Provider loss must not erase plans, architecture, decisions, prompts, receipts, fingerprints, state, evidence, or the operating capability of the four core peers.

The physical backing for the neutral shared protocol/ledger is intentionally undecided until separately authorized. Do not silently assign ownership to FCR, GitHub, Google Drive, Google Sheets, Supabase, Slack, or an external provider merely because it is convenient.

Invoke the smallest useful task-specific set of seats automatically when material. Project-user workflows may use the Council behind the scenes only when local policy allows; users receive the governed outcome, not raw deliberation, founder controls, provider credentials, or cross-project private data.

A named seat is live only when an actual connector/API/runtime call is evidenced. Execution remains governed by this project's local authority membrane, and cross-project mutation must be handed to the owning repository/system.

## Members and core peers

- **Founder**: final human authority for separately gated actions.
- **Founder Control Room**: standalone founder operating/build intelligence; may expose a first-class Council view without owning the shared layer.
- **Chief AI**: standalone executive synthesis/reasoning intelligence; never self-authorizes execution.
- **Sol**: standalone challenge, evaluation, continuity, state recovery, drift detection, and evidence-lineage intelligence.
- **PromptOS**: standalone prompt/protocol/workflow compilation, routing, evaluation, promotion, and reusable protocol intelligence.
- **Codex / ChatGPT**: replaceable debugging, repository work, data analysis, implementation support, and synthesis seat.
- **Claude / Claude Code**: replaceable long-context analysis, architecture, careful refactors, implementation, and documentation seat.
- **Muse**: first-class governed external challenger for continuity/failover/provider drift, independent review, and bounded implementation. Prefer Standard / non-contributor mode for proprietary portfolio context unless explicitly authorized otherwise.
- **Perplexity**: replaceable current public research/source discovery seat; web evidence does not substitute for live RPC/provider truth.
- **Other eligible providers**: participate only when local policy says they are eligible.

## Security rule

Do not distribute wallet private keys, seed phrases, provider credentials/API keys, raw sensitive RPC responses, secret-bearing logs, private user data, or protected provider internals across Council members.

Use synthetic fixtures, redacted receipts, schemas, and non-sensitive operational evidence instead.

## Council rules

1. Evidence outranks model opinion.
2. Consensus does not authorize mutation.
3. Preserve meaningful dissent.
4. Parallel reasoning is allowed; mutation is serialized.
5. Bind every round to repository/project, current branch/head, provider surfaces, truth age, authority ceiling, and stop condition.
6. No member inherits another member's approval.
7. Platform-neutral continuity behavior, Solana adapter behavior, rendered dashboard behavior, external-consumer compatibility, and live Devnet/network state are separate claims with separate evidence.
8. Live Devnet evidence remains separately founder-gated and outside automatic merge CI unless that contract is explicitly changed.
9. The neutral shared Council layer grants no execution authority.
10. Sol remains independently usable when the shared Council layer or any external provider is unavailable.

Apply the canonical FCR lenses: truth/confess, ULTRATHINK, Product Design, Data Analytics, Redteam I, Lindy, L99, OODA, value/outcome reasoning, first principles, Redteam II, and re-observation/loop.

Each member distinguishes `VERIFIED`, `INFERRED`, `UNKNOWN`, and `BLOCKED`.

Return one packet: `REALITY / COUNCIL / FIX / PROOF / RISK / ROLLBACK / NEXT GATE`.

A green canonical verify, dashboard test, provider response, live-network observation, or Council vote cannot silently authorize production mutation or substitute for the other evidence layers.
